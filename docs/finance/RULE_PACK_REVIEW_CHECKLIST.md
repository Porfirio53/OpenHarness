# 三个首批规则包财务复核清单

## 复核结论格式

请对每个场景填写“同意 / 修改后同意 / 暂不启用”，并记录确认人、确认日期、适用单位、
制度生效日期和修改意见。口头确认不能直接把规则包改成 `active`。

## 国内差旅费

对应文件：`rule_packs/travel_domestic.yaml`。

- 是否仅覆盖境内公务出差，并排除港澳台、境外和商旅统结单独报账；
- 线下差旅申请、非统结发票、第三方打车行程单的条件是否准确；
- 非统结酒店账单明细和支付凭证是否均为必需；
- 行程变化、因私绕道、跨期报账的材料和审批提示是否准确；
- 生产、管理、营销、研发部门的业务活动映射是否为当前有效版本；
- 表4、表5的定位是否与当前正式手册一致。

## 会议费

对应文件：`rule_packs/meeting_expense.yaml`。

- 公司组织会议与参加外部会议的边界是否准确；
- 会议通知是否始终需要，事前申请和签到是否仅适用于公司组织会议；
- 酒店费用清单的触发条件、盖章要求是否准确；
- 个人垫付超过5000元的支付记录要求是否仍然有效；
- 酒店清单人数与签到人数不一致时的处理方式是否准确；
- 外部会议免签到表、免酒店清单的例外是否有其他前提；
- 多服务类型分行分税目的提示是否应阻断或转人工；
- 表26–29及业财映射的定位是否为当前有效版本。

## IT维护支撑费正式报账

对应文件：`rule_packs/it_maintenance_support.yaml`。

- 首月是否仅覆盖正式报账，并排除计提、冲销；
- B域、M域、O域、IT云和其他IT维护支撑的定义及业务活动是否准确；
- 发票、合同/采购订单、双方确认结算单是否均为正式报账必需材料；
- 合同约定的验收、考核、请款、账户变更等材料触发方式是否准确；
- 结算单最小字段、合同/订单/结算单一致性要求是否准确；
- 金额差异和账号差异应阻断、转人工还是允许补充说明；
- 表42–45、业财映射和现金流映射是否为当前有效版本。

## 来源和发布检查

对应文件：`source_manifest.yaml`。

- 文件校验和是否对应财务确认的原始文件；
- 成本费用域手册2025V1是否适用于当前试点单位；
- 预算流程、业务场景表、业财映射和现金流映射的正式版本及生效日期；
- 是否存在更新制度或本地口径与候选规则冲突；
- 所有冲突是否已有负责人和解决日期；
- 批准后是否保留旧版本，使用新版本号发布，确保可以回滚。

复核完成前，所有财务来源和三个规则包必须保持 `review_required`。如果任何关键问题无法
确认，维持候选状态并由后续 Harness 返回人工复核，不得给出“材料齐全”结论。
